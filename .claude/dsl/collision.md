# DSL reference: Collision

The whole story of these verbs. The one-line index is `.claude/rules/dsl-reference.md`.

- `box x, y, w, h` → a `Box` (a rectangle to test; draws nothing). Coords may be `:var`/`Value`/`Integer`.
- **Screen-edge tests** (on anything with bounds — a `Sprite` or a `Box`): `off_screen?` (fully past any edge), and edge-specific `off_left?` / `off_right?` / `above_top?` / `below_bottom?` for when behavior depends on *which* edge (a bullet dies off the top, an enemy respawns off the bottom) — each returns a `Condition` for `.then`, read from the thing's own bounds and the 240×160 screen, so no coordinate literals. Pair with `sprite.clamp_to_screen` (keep it fully on screen using its own size). "Fully past" means nothing of it still shows.
- `a.overlaps?(b)` → a `Condition`; `.then { }` on it. Works on any two things with bounds — a `Box`, or a `Sprite` (which provides its own bounds), so `hero.overlaps?(coin)` needs no box. **Sprite-vs-sprite is per-pixel by default** (`sprite … hitbox:` picks the box): a hit needs the two sprites' *drawn* pixels to actually meet, any shape, following whichever animation frame is showing — a cheap box test gates it so far-apart pairs stay cheap. A `Box` (and a sprite given an explicit `hitbox:`) collides on its plain rectangle instead, so sprite-vs-box is a box test. Set a sprite's box with `hitbox:` (see the sprite verb): `:full` (whole image), an inset number (shrink each side), or `[x, y, w, h]`; the default box (used as the per-pixel gate, or as the collision box when you opt out) hugs the visible pixels.
- **Tile collision (tiled mode):** mark walls with `tiles ..., solid: ["#"]`, then `sprite.blocked_by(background)` — its `move` is checked automatically (stops at walls, slides along them). `sprite.can_move?(:left, by: n)` → a `Condition` for manual control; raw `move_to`/`x`/`y` are never checked (escape hatch). **A `pool` takes it too** — `guards.blocked_by(room)` once, and then every instance's `move` and `can_move?` are checked inside `each`, each sliding along walls on its own. That is the case that most wants it: a game with a roomful of movers. **What it costs does not depend on the room.** The framework asks the map whether the cell a mover is stepping into is solid, so a bare room and a maze of pillars are the same handful of reads — where testing the mover against every wall rectangle cost what the room was made of, and was written out afresh at every place a thing moved. Measured on a 30x20 room, eight movers: the game loop went from 353K, which does not fit the console's quick memory and drops the *whole* frame to cartridge speed, to 3K, which does. The check is one shared routine, so a second mover costs a call rather than another copy, and a pool of thirty-two shares it with a hand-declared sprite of the same size. Walking off the edge of the map is not blocked (there is nothing there to be solid), same as before.
