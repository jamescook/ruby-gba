# DSL reference: Input

The whole story of these verbs. The one-line index is `.claude/rules/dsl-reference.md`.

- `held(:left)` — 1 while down; `pressed(:start)` — 1 on the press edge only. Use with `.then { }`.
- `held(:any)` / `pressed(:any)` — **any button at all**, which is how a game leaves an attract screen, a splash or a cut scene: `pressed(:any).then { mode.set! :title }`. `pressed(:any)` is true on a frame some button went down, the same edge each button has on its own — so A pressed while LEFT is still held counts, and a button held on and on is one press. It is one test against all ten buttons, cheaper than the ten `held` tests joined with `|` it replaces, and none can be left out. `:any` is not a button: a test's `hold(...)` and the command line's held keys refuse it, since holding "any" means nothing.
- Low-level: `if_held(:a) { }` / `if_pressed(:a) { }`. Buttons: `a b select start right left up down r l`.
- `rumble frames: 12, pattern: "##..##.."` — **shake the player's hands**, as a ball hitting a bumper does. The motor runs for `frames:` frames (0 to 65535), on or off on each by the pattern: eight frames, `"#"` on and `"."` off, read from the left and round again after the eighth. Steady by default; `"#.#.#.#."` is a light buzz. A number 0–255 is read as the Color's own games read theirs — turned a bit to the right each frame and the lowest bit read, so its frames come from bit 1 up to bit 7 and then bit 0 — and a pattern taken from one of them (Pokémon Pinball's `wRumblePattern`) plays the same (`IR::Rumble`). A rumble said while one runs takes its place, and `frames: 0` stops it. It starts on the frame after the pass that says it, and moves on with every frame shown, a slow pass's too (Pokémon Pinball counts its rumble down a pass at a time instead, which is the same while the game keeps up). A game that halts stops the motor. **Where it is felt**: on a console whose cartridge carries a motor — the Game Boy Color's, whose cartridge then says so in its header. On any other it does nothing, and the game plays the same (see each console's page). A Color cartridge with a `clock` has no motor, so a Color game that uses both is refused. **In a test**: `motor_on?` on the interpreter, a checked run and the emulator's reader says whether the motor runs on the frame shown; the checked run compares it on every pass. **What it costs**: on the Color, a few bytes of work memory, a short routine each frame shown, and two writes where it is said; a game that never says it builds the same bytes. Worked example: `test/all/vblank/builder/test_rumble.rb`, `test/lowering/gbc/vblank/ir/backends/gbc/test_gbc_rumble.rb`.
